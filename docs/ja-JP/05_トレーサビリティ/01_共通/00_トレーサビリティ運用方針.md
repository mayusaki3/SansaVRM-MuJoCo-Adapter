# トレーサビリティ運用方針

## 1. 本ドキュメントの目的

本ドキュメントは、SansaVRM-MuJoCo-Adapter における要件、仕様、テスト仕様、実装計画、実装コード、テストコードの対応関係を管理するための運用方針を定義する。

トレーサビリティは、仕様変更時に影響範囲を確認し、実装とテストの抜け漏れを防ぐために使用する。

## 2. 基本方針

本リポジトリでは、以下の対応関係を追跡する。

- 要件定義から仕様への対応
- 仕様からテスト仕様への対応
- テスト仕様からテストコードへの対応
- 仕様から実装コードへの対応
- 実装計画から作業成果物への対応
- diagnostics / conversion_report から変換判断への対応

## 3. 管理対象

トレーサビリティの管理対象は以下とする。

- 要件定義ドキュメント
- 仕様ドキュメント
- テスト仕様ドキュメント
- 実装計画ドキュメント
- schema ファイル
- source code
- test code
- examples
- fixtures
- diagnostics sample
- conversion_report sample

## 5. ID運用

HLDocS の `doc_id` は、ドキュメント単位の識別子として使用する。

テスト仕様では、テスト番号を識別子として使用する。

テスト番号は以下の形式とする。

```text
T-<AREA>-<NUMBER>
```

例：

```text
T-LOCAL-001
T-MJCF-001
T-ACTUATOR-001
T-CONTROLLERCONFIG-001
```

## 6. 要件から仕様への対応方針

要件定義で定義した内容は、仕様ドキュメントのいずれかに対応させる。

初期対応例は以下とする。

| 要件 | 対応仕様 |
| --- | --- |
| 目的 | 仕様概要 |
| 対象範囲 | 仕様概要 / MJCF変換方針 / 成果物仕様 |
| 責務境界 | AdapterAPI前提 / 成果物仕様 |
| ローカル検証要件 | MJCF変換方針 / MuJoCoバージョン対応方針 |

## 7. 仕様からテスト仕様への対応方針

仕様ドキュメントで定義した内容は、対応するテスト仕様へ接続する。

初期対応例は以下とする。

| 仕様 | 対応テスト仕様 |
| --- | --- |
| 仕様概要 | テスト方針 |
| 成果物仕様 | テスト結果レポート仕様 / controller_configテスト仕様 |
| diagnostics仕様 | テスト結果レポート仕様 / controller_configテスト仕様 |
| MJCF変換方針 | MJCF読み込みテスト仕様 |
| アクチュエータ写像 | アクチュエータ写像テスト仕様 |
| custom parameter mapping | アクチュエータ写像テスト仕様 / controller_configテスト仕様 |
| controller_config仕様 | controller_configテスト仕様 |
| MuJoCoバージョン対応方針 | ローカル動作確認テスト仕様 / MJCF読み込みテスト仕様 |

## 8. テスト仕様からテストコードへの対応方針

テスト仕様で定義したテスト番号は、テストコード内の test 関数と対応させる。

対応例は以下とする。

| テスト番号 | テストコード候補 |
| --- | --- |
| T-LOCAL-001 | `tests/mujoco/test_local_mujoco_environment.py` |
| T-MJCF-001 | `tests/mujoco/test_mjcf_loading.py` |
| T-ACTUATOR-001 | `tests/mujoco/test_actuator_mapping.py` |
| T-CONTROLLERCONFIG-001 | `tests/mujoco/test_controller_config.py` |

pytest の test 関数名には、可能な範囲でテスト番号を含める。

例：

```text
test_t_local_001_import_mujoco
test_t_mjcf_001_load_minimal_body
```

## 9. 仕様から実装コードへの対応方針

仕様ドキュメントで定義した機能は、実装コードの責務単位へ対応させる。

初期実装候補は以下とする。

| 仕様 | 実装候補 |
| --- | --- |
| diagnostics仕様 | `src/sansavrm_mujoco_adapter/diagnostics.py` |
| controller_config仕様 | `src/sansavrm_mujoco_adapter/controller_config.py` |
| MJCF変換方針 | `src/sansavrm_mujoco_adapter/mjcf_writer.py` |
| custom parameter mapping | `src/sansavrm_mujoco_adapter/custom_parameter_mapping.py` |
| MuJoCoバージョン対応方針 | `src/sansavrm_mujoco_adapter/version_policy.py` |

## 10. 実装計画から成果物への対応方針

実装計画は、作業順序と成果物を接続する。

初期対応例は以下とする。

| 実装計画 | 成果物 |
| --- | --- |
| 開発環境構築 | `.venv`, `requirements-dev.txt`, `.gitignore` |
| 初版実装ロードマップ | `tests/`, `src/`, `schemas/`, `examples/` |
| ローカルMuJoCo環境構築 | `requirements-dev.txt`, `examples/mujoco/minimal_body/model.xml` |
| ローカル動作確認手順 | manual command / pytest |
| 最小MJCF検証計画 | `tests/mujoco/test_mjcf_loading.py` |

## 11. diagnosticsとの関係

diagnostics は、変換・検証時の判断理由を記録する成果物である。

diagnostics の `code`、`target_type`、`target_id`、`source` は、対応する仕様、テスト、実装箇所を追跡できるように設計する。

## 12. conversion_reportとの関係

conversion_report は、変換結果の概要と集計を記録する成果物である。

conversion_report は、個別の判断詳細を diagnostics に委譲し、集計と概要を保持する。

## 13. 変更時の運用

仕様を変更する場合は、以下を確認する。

1. 要件定義への影響
2. 仕様ドキュメントへの影響
3. テスト仕様への影響
4. テストコードへの影響
5. 実装コードへの影響
6. schema への影響
7. 目次リンクへの影響

## 14. 目次リンク確認

ドキュメントを追加または移動した場合、`docs/ja-JP/目次.md` を更新する。

作成済みドキュメントはリンク化する。

未作成ドキュメントはコード表記のまま残す。

ドキュメントから目次へ戻る階層リンクは、以下を使用する。

```markdown
[目次](../../目次.md)
```

## 15. Git管理方針

以下は Git 管理対象とする。

- トレーサビリティ運用方針
- 小規模な schema
- 小規模な fixture
- テスト仕様
- 実装コード
- テストコード

以下は Git 管理対象外とする。

- ローカル実行ログ
- ローカル test report
- ローカル diagnostics
- ローカル conversion_report
- compiled binary model

## 16. 非スコープ

本ドキュメントでは、以下を非スコープとする。

- 完全なトレーサビリティマトリクスの作成
- 外部要件管理ツール連携
- CI 上の trace report 自動生成
- UI 表示仕様

## 17. 次工程

本運用方針の次工程は以下とする。

1. 最小 schema の作成
2. 最小 fixture の作成
3. pytest テストコードの作成
4. 実装コード skeleton の作成
5. テスト番号と test 関数の対応確認
