# ローカル動作確認テスト仕様

## 1. 本ドキュメントの目的

本ドキュメントは、SansaVRM-MuJoCo-Adapter のローカル MuJoCo 環境が最小動作条件を満たしていることを確認するためのテスト仕様を定義する。

本テスト仕様は、実装前の環境確認、MJCF 読み込みテスト、将来の pytest 化の前提として使用する。

## 2. 基本方針

ローカル動作確認テストは、headless 実行を基本とする。

MuJoCo viewer の起動確認は初期必須テストに含めない。

本テストでは、`examples/mujoco/minimal_body/model.xml` を最小検証モデルとして使用する。

## 3. 前提条件

以下が完了していること。

- Python 仮想環境 `.venv` が作成されている
- `requirements-dev.txt` に基づき依存関係がインストールされている
- `mujoco` package が使用可能である
- `examples/mujoco/minimal_body/model.xml` が存在する
- リポジトリ直下でテストを実行する

## 4. 対象ファイル

対象ファイルは以下とする。

```text
examples/mujoco/minimal_body/model.xml
```

## 5. テスト一覧

| テスト番号 | テスト名 | 目的 |
| --- | --- | --- |
| T-LOCAL-001 | mujoco import確認 | `mujoco` package を import できることを確認する |
| T-LOCAL-002 | 最小MJCF読み込み確認 | 最小 MJCF モデルを読み込めることを確認する |
| T-LOCAL-003 | MjData生成確認 | `MjModel` から `MjData` を生成できることを確認する |
| T-LOCAL-004 | mj_step実行確認 | `mj_step` を 1 回以上実行できることを確認する |
| T-LOCAL-005 | 要素数確認 | body / geom 数が期待範囲内であることを確認する |

## 6. T-LOCAL-001: mujoco import確認

### 6.1 目的

Python 環境で `mujoco` package を import できることを確認する。

### 6.2 入力

なし。

### 6.3 実行内容

```powershell
python -c "import mujoco; print(mujoco.__version__)"
```

### 6.4 期待結果

- 終了コードが 0 である
- `mujoco.__version__` が表示される

### 6.5 失敗時の扱い

失敗した場合は、ローカル環境構築未完了として扱う。

## 7. T-LOCAL-002: 最小MJCF読み込み確認

### 7.1 目的

最小 MJCF モデルを `MjModel` として読み込めることを確認する。

### 7.2 入力

```text
examples/mujoco/minimal_body/model.xml
```

### 7.3 実行内容

```powershell
python -c "import mujoco; m=mujoco.MjModel.from_xml_path('examples/mujoco/minimal_body/model.xml'); print('ok', m.nbody, m.ngeom)"
```

### 7.4 期待結果

- 終了コードが 0 である
- `MjModel.from_xml_path` が例外を出さない
- `ok` が表示される

### 7.5 失敗時の扱い

失敗した場合は、MJCF ファイル不正または MuJoCo 実行環境不備として扱う。

## 8. T-LOCAL-003: MjData生成確認

### 8.1 目的

読み込んだ `MjModel` から `MjData` を生成できることを確認する。

### 8.2 入力

```text
examples/mujoco/minimal_body/model.xml
```

### 8.3 実行内容

```powershell
python -c "import mujoco; m=mujoco.MjModel.from_xml_path('examples/mujoco/minimal_body/model.xml'); d=mujoco.MjData(m); print('ok')"
```

### 8.4 期待結果

- 終了コードが 0 である
- `MjData` の生成で例外が発生しない
- `ok` が表示される

### 8.5 失敗時の扱い

失敗した場合は、MuJoCo model/data 初期化不備として扱う。

## 9. T-LOCAL-004: mj_step実行確認

### 9.1 目的

MuJoCo の step 実行が可能であることを確認する。

### 9.2 入力

```text
examples/mujoco/minimal_body/model.xml
```

### 9.3 実行内容

```powershell
python -c "import mujoco; m=mujoco.MjModel.from_xml_path('examples/mujoco/minimal_body/model.xml'); d=mujoco.MjData(m); mujoco.mj_step(m,d); print('ok')"
```

### 9.4 期待結果

- 終了コードが 0 である
- `mj_step` が例外を出さない
- `ok` が表示される

### 9.5 失敗時の扱い

失敗した場合は、MuJoCo headless 実行不備として扱う。

## 10. T-LOCAL-005: 要素数確認

### 10.1 目的

最小 MJCF モデルの body / geom 数が期待範囲内であることを確認する。

### 10.2 入力

```text
examples/mujoco/minimal_body/model.xml
```

### 10.3 実行内容

```powershell
python -c "import mujoco; m=mujoco.MjModel.from_xml_path('examples/mujoco/minimal_body/model.xml'); print(m.nbody, m.ngeom)"
```

### 10.4 期待結果

- 終了コードが 0 である
- `nbody >= 1` である
- `ngeom >= 1` である

### 10.5 失敗時の扱い

失敗した場合は、最小検証モデルの構造不備として扱う。

## 11. pytest化方針

本テスト仕様は、将来的に `pytest` により自動化する。

初期配置候補は以下とする。

```text
tests/mujoco/test_local_mujoco_environment.py
```

pytest 実装時は、各テスト番号と test 関数を対応付ける。

例：

```text
T-LOCAL-001 -> test_t_local_001_import_mujoco
T-LOCAL-002 -> test_t_local_002_load_minimal_mjcf
```

## 12. テスト結果レポートへの記録

テスト結果は、必要に応じて `test_report.local.json` に記録する。

`test_report.local.json` は Git 管理対象外とする。

記録対象は以下とする。

- test_id
- status
- command
- expected
- actual
- duration_ms
- diagnostics_ref

## 13. diagnosticsとの関係

ローカル動作確認で失敗した場合、diagnostics に以下を記録してよい。

- mujoco import failure
- MJCF load failure
- MjData initialization failure
- mj_step failure
- invalid minimal model structure

## 14. 非スコープ

本ドキュメントでは、以下を非スコープとする。

- MuJoCo viewer 起動確認
- OS / GPU / OpenGL 互換性テスト
- CI workflow の詳細
- MJCF 変換ロジックの検証
- actuator 写像の検証
