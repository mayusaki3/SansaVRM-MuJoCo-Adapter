# アクチュエータ写像テスト仕様

## 1. 本ドキュメントの目的

本ドキュメントは、SansaVRM-MuJoCo-Adapter におけるアクチュエータ写像のテスト仕様を定義する。

本テスト仕様は、SansaVRM actuator 情報を MuJoCo actuator、controller_config、diagnostics、conversion_report へ正しく分類・出力できることを確認するために使用する。

## 2. 基本方針

アクチュエータ写像テストでは、以下を確認する。

- position control を MuJoCo position actuator へ写像できる
- velocity control を MuJoCo velocity actuator へ写像できる
- torque / force control を MuJoCo motor actuator へ写像できる
- MJCF に直接出力しない情報を controller_config へ分離できる
- fallback、非可逆変換、未対応情報を diagnostics へ記録できる

## 3. 前提条件

以下が完了していること。

- ローカル MuJoCo 環境が構築されている
- MJCF 読み込みテストが実行可能である
- アクチュエータ写像仕様が定義されている
- custom parameter mapping 仕様が定義されている
- controller_config 仕様が定義されている

## 4. テスト対象

テスト対象は以下とする。

- actuator control mode mapping
- position actuator mapping
- velocity actuator mapping
- motor actuator mapping
- torque limit mapping
- velocity limit mapping
- command delay separation
- deadband separation
- current limit / voltage limit handling
- diagnostics output
- conversion_report output

## 6. T-ACTUATOR-001: position actuator写像

### 6.1 目的

SansaVRM の position control actuator を MuJoCo の `position` actuator へ写像できることを確認する。

### 6.2 入力

position control actuator を含む fixture を入力とする。

初期 fixture 候補：

```text
tests/fixtures/actuator/position_actuator.json
```

### 6.3 期待結果

- MJCF に `position` actuator が出力される
- target joint が正しく参照される
- `kp` が出力される
- `ctrlrange` が出力される
- `forcerange` が必要に応じて出力される
- 出力 MJCF を MuJoCo で読み込める

### 6.4 diagnostics期待結果

通常成功時は error / fatal を出力しない。

近似変換がある場合は warning または info として記録してよい。

## 7. T-ACTUATOR-002: velocity actuator写像

### 7.1 目的

SansaVRM の velocity control actuator を MuJoCo の `velocity` actuator へ写像できることを確認する。

### 7.2 入力

velocity control actuator を含む fixture を入力とする。

初期 fixture 候補：

```text
tests/fixtures/actuator/velocity_actuator.json
```

### 7.3 期待結果

- MJCF に `velocity` actuator が出力される
- target joint が正しく参照される
- `kv` が出力される
- velocity limit が `ctrlrange` または controller_config へ正しく分類される
- 出力 MJCF を MuJoCo で読み込める

### 7.4 diagnostics期待結果

通常成功時は error / fatal を出力しない。

MJCF に直接表現しない velocity limit がある場合は、controller_config への分離を info として記録してよい。

## 8. T-ACTUATOR-003: torque actuator写像

### 8.1 目的

SansaVRM の torque control actuator を MuJoCo の `motor` actuator へ写像できることを確認する。

### 8.2 入力

torque control actuator を含む fixture を入力とする。

初期 fixture 候補：

```text
tests/fixtures/actuator/torque_actuator.json
```

### 8.3 期待結果

- MJCF に `motor` actuator が出力される
- target joint が正しく参照される
- `gear` が必要に応じて出力される
- `forcerange` が必要に応じて出力される
- 外部制御が必要な情報は controller_config へ分離される
- 出力 MJCF を MuJoCo で読み込める

### 8.4 diagnostics期待結果

外部制御前提の情報を controller_config へ分離した場合、info または warning として記録する。

## 9. T-ACTUATOR-004: command delay分離

### 9.1 目的

command delay を MJCF へ直接出力せず、controller_config へ分離できることを確認する。

### 9.2 入力

command delay を持つ actuator fixture を入力とする。

### 9.3 期待結果

- MJCF に command delay 相当の独自属性を出力しない
- controller_config に `command_delay_ms` を出力する
- diagnostics に分離情報を記録できる

### 9.4 diagnostics期待結果

以下を info として記録してよい。

- command delay を controller_config へ分離した

## 10. T-ACTUATOR-005: deadband分離

### 10.1 目的

deadband を MJCF へ直接出力せず、controller_config へ分離できることを確認する。

### 10.2 入力

deadband を持つ actuator fixture を入力とする。

### 10.3 期待結果

- MJCF に deadband 相当の独自属性を出力しない
- controller_config に `deadband_rad` または schema で定義された deadband 項目を出力する
- diagnostics に分離情報を記録できる

### 10.4 diagnostics期待結果

以下を info として記録してよい。

- deadband を controller_config へ分離した

## 11. T-ACTUATOR-006: torque limit写像

### 11.1 目的

torque limit を MJCF の `forcerange` または controller_config へ正しく分類できることを確認する。

### 11.2 入力

torque limit を持つ actuator fixture を入力とする。

### 11.3 期待結果

- `io_scope = mjcf` の場合、MJCF の `forcerange` へ出力する
- `io_scope = adapter_artifact` の場合、controller_config へ出力する
- `io_scope = both` の場合、MJCF と controller_config の両方へ出力する
- 単一の正値から対称範囲へ変換する場合、value_conversion に従う

### 11.4 diagnostics期待結果

以下を diagnostics に記録できる。

- value_conversion 適用
- fallback 適用
- controller_config への分離

## 12. T-ACTUATOR-007: 未対応control mode診断

### 12.1 目的

未対応の control mode を検出し、diagnostics に記録できることを確認する。

### 12.2 入力

未対応 control mode を持つ actuator fixture を入力とする。

### 12.3 期待結果

- MJCF へ actuator を出力しない、または fallback 方針に従う
- diagnostics に unsupported control mode を記録する
- conversion_report に変換除外または fallback 適用を記録する

### 12.4 diagnostics期待結果

severity は `warning` または `error` とする。

変換処理全体を継続できない場合のみ `fatal` とする。

## 13. pytest化方針

本テスト仕様は、将来的に `pytest` により自動化する。

初期配置候補は以下とする。

```text
tests/mujoco/test_actuator_mapping.py
```

pytest 実装時は、各テスト番号と test 関数を対応付ける。

例：

```text
T-ACTUATOR-001 -> test_t_actuator_001_position_actuator_mapping
T-ACTUATOR-004 -> test_t_actuator_004_command_delay_to_controller_config
```

## 14. テスト結果レポートへの記録

テスト結果は、必要に応じて `test_report.local.json` に記録する。

記録対象は以下とする。

- test_id
- status
- input_fixture
- generated_mjcf_path
- generated_controller_config_path
- diagnostics_ref
- conversion_report_ref

## 15. diagnosticsとの関係

アクチュエータ写像テストで失敗または分離が発生した場合、diagnostics に以下を記録してよい。

- unsupported actuator type
- unsupported control mode
- missing target joint
- missing required actuator parameter
- invalid torque limit
- invalid unit
- controller_config separation
- fallback applied

## 16. 非スコープ

本ドキュメントでは、以下を非スコープとする。

- controller runtime の実装検証
- 実サーボ内部ファームウェアの完全再現
- 熱シミュレーションの詳細検証
- FOC 制御の詳細検証
- 実機との sysid 検証
