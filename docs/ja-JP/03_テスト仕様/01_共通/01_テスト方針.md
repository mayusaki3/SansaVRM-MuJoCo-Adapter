# テスト方針

## 1. 本ドキュメントの目的

本ドキュメントは、SansaVRM-MuJoCo-Adapter における共通テスト方針を定義する。

本方針は、要件定義、仕様、実装計画、実装コード、テストコードを段階的に対応付け、MuJoCo / MJCF / controller_config / diagnostics の検証を再現可能にするために定義する。

## 2. 基本方針

テストは、以下の順に整備する。

1. 要件定義の確認
2. 仕様の確認
3. テスト仕様の作成
4. テストケースの作成
5. 実装コードの作成
6. 自動テストの実行
7. テスト結果の記録

実装コードは、対応するテスト仕様とテストケースを定義した後に作成する。

## 3. テスト分類

本リポジトリでは、以下のテスト分類を使用する。

- ローカル環境テスト
- MJCF読み込みテスト
- MJCF変換テスト
- アクチュエータ写像テスト
- custom parameter mapping テスト
- controller_config テスト
- diagnostics テスト
- conversion_report テスト
- regression テスト

## 4. テスト番号体系

テストには必ずテスト番号を付与する。

テスト番号は以下の形式を基本とする。

```text
T-<AREA>-<NUMBER>
```

初期の AREA は以下とする。

- `LOCAL`
- `MJCF`
- `ACTUATOR`
- `CUSTOMPARAM`
- `CONTROLLERCONFIG`
- `DIAGNOSTICS`
- `CONVERSIONREPORT`
- `REGRESSION`

例：

```text
T-LOCAL-001
T-MJCF-001
T-ACTUATOR-001
```

## 5. ローカル環境テスト

ローカル環境テストは、MuJoCo Python 環境が使用可能であることを確認する。

初期テストは以下とする。

| テスト番号 | テスト名 | 目的 |
| --- | --- | --- |
| T-LOCAL-001 | mujoco import確認 | `mujoco` package を import できることを確認する |
| T-LOCAL-002 | 最小MJCF読み込み確認 | `examples/mujoco/minimal_body/model.xml` を読み込めることを確認する |
| T-LOCAL-003 | MjData生成確認 | 読み込んだ `MjModel` から `MjData` を生成できることを確認する |
| T-LOCAL-004 | mj_step実行確認 | `mj_step` を 1 回以上実行できることを確認する |
| T-LOCAL-005 | 要素数確認 | body / geom 数が期待範囲内であることを確認する |

## 6. MJCF読み込みテスト

MJCF読み込みテストは、生成済みまたはサンプルの MJCF が MuJoCo で読み込めることを確認する。

初期テストは以下とする。

| テスト番号 | テスト名 | 目的 |
| --- | --- | --- |
| T-MJCF-001 | 最小bodyモデル読み込み | 最小 body / geom を持つ MJCF を読み込めることを確認する |
| T-MJCF-002 | joint付きモデル読み込み | joint を持つ MJCF を読み込めることを確認する |
| T-MJCF-003 | actuator付きモデル読み込み | actuator を持つ MJCF を読み込めることを確認する |
| T-MJCF-004 | sensor付きモデル読み込み | sensor を持つ MJCF を読み込めることを確認する |

## 7. MJCF変換テスト

MJCF変換テストは、SansaVRM API から取得した情報を MJCF へ変換できることを確認する。

初期段階では、SansaVRM 本体 API が未確定であるため、fixture または mock input を使用する。

初期テストは以下とする。

| テスト番号 | テスト名 | 目的 |
| --- | --- | --- |
| T-MJCF-101 | body変換確認 | module 相当情報から body を生成できることを確認する |
| T-MJCF-102 | joint変換確認 | joint 情報から MJCF joint を生成できることを確認する |
| T-MJCF-103 | geom変換確認 | collider 情報から MJCF geom を生成できることを確認する |
| T-MJCF-104 | 最小MJCF出力確認 | 生成した MJCF を MuJoCo で読み込めることを確認する |

## 8. アクチュエータ写像テスト

アクチュエータ写像テストは、SansaVRM actuator 情報を MuJoCo actuator または controller_config へ正しく分離できることを確認する。

初期テストは以下とする。

| テスト番号 | テスト名 | 目的 |
| --- | --- | --- |
| T-ACTUATOR-001 | position actuator写像 | position control を MuJoCo position actuator へ写像できることを確認する |
| T-ACTUATOR-002 | velocity actuator写像 | velocity control を MuJoCo velocity actuator へ写像できることを確認する |
| T-ACTUATOR-003 | torque actuator写像 | torque control を MuJoCo motor actuator へ写像できることを確認する |
| T-ACTUATOR-004 | command delay分離 | command delay を controller_config へ分離できることを確認する |
| T-ACTUATOR-005 | deadband分離 | deadband を controller_config へ分離できることを確認する |

## 9. custom parameter mappingテスト

custom parameter mapping テストは、custom parameter schema に基づいて出力先を分類できることを確認する。

初期テストは以下とする。

| テスト番号 | テスト名 | 目的 |
| --- | --- | --- |
| T-CUSTOMPARAM-001 | io_scope=mjcf分類 | MJCF 出力対象として分類できることを確認する |
| T-CUSTOMPARAM-002 | io_scope=adapter_artifact分類 | Adapter 補助成果物対象として分類できることを確認する |
| T-CUSTOMPARAM-003 | io_scope=both分類 | MJCF と補助成果物の両方へ分類できることを確認する |
| T-CUSTOMPARAM-004 | io_scope=preserve_only分類 | 保持のみとして分類できることを確認する |
| T-CUSTOMPARAM-005 | unsupported記録 | 未対応 parameter を diagnostics に記録できることを確認する |

## 10. controller_configテスト

controller_config テストは、MJCF に直接出力しない制御・実行補助情報を controller_config に出力できることを確認する。

初期テストは以下とする。

| テスト番号 | テスト名 | 目的 |
| --- | --- | --- |
| T-CONTROLLERCONFIG-001 | controller_config生成 | controller_config を生成できることを確認する |
| T-CONTROLLERCONFIG-002 | actuator設定出力 | actuator 単位の設定を出力できることを確認する |
| T-CONTROLLERCONFIG-003 | command_delay出力 | command_delay を出力できることを確認する |
| T-CONTROLLERCONFIG-004 | deadband出力 | deadband を出力できることを確認する |
| T-CONTROLLERCONFIG-005 | diagnostics参照保持 | diagnostics_ref を保持できることを確認する |

## 11. diagnosticsテスト

diagnostics テストは、変換・検証時の警告、エラー、補足情報を正しく記録できることを確認する。

初期テストは以下とする。

| テスト番号 | テスト名 | 目的 |
| --- | --- | --- |
| T-DIAGNOSTICS-001 | info記録 | info severity を記録できることを確認する |
| T-DIAGNOSTICS-002 | warning記録 | warning severity を記録できることを確認する |
| T-DIAGNOSTICS-003 | error記録 | error severity を記録できることを確認する |
| T-DIAGNOSTICS-004 | fatal記録 | fatal severity を記録できることを確認する |
| T-DIAGNOSTICS-005 | target情報記録 | target_type / target_id を記録できることを確認する |

## 12. conversion_reportテスト

conversion_report テストは、変換結果の概要、集計、fallback、非可逆情報を記録できることを確認する。

初期テストは以下とする。

| テスト番号 | テスト名 | 目的 |
| --- | --- | --- |
| T-CONVERSIONREPORT-001 | 変換件数記録 | 変換対象数、成功数、除外数を記録できることを確認する |
| T-CONVERSIONREPORT-002 | fallback集計 | fallback 適用数を記録できることを確認する |
| T-CONVERSIONREPORT-003 | warning/error集計 | warning / error 数を記録できることを確認する |
| T-CONVERSIONREPORT-004 | version情報記録 | target MuJoCo version を記録できることを確認する |

## 13. regressionテスト

regression テストは、既存の変換結果や仕様で定義した期待挙動が破壊されていないことを確認する。

初期段階では、以下を対象とする。

- 最小 MJCF サンプル
- position actuator サンプル
- motor actuator サンプル
- custom parameter mapping サンプル
- controller_config サンプル

## 14. カバレッジ方針

単体テストを作成する場合、対象モジュールのカバレッジ率は 100% を目標ではなく必須とする。

ただし、MuJoCo viewer、OS / GPU / OpenGL 依存箇所、外部 runtime に依存する箇所は、単体テスト対象から分離し、統合テストまたは手動検証に分類する。

## 15. Git管理方針

以下は Git 管理対象とする。

- テスト仕様ドキュメント
- 小規模な fixture
- 小規模な期待結果ファイル
- テストコード

以下は Git 管理対象外とする。

- ローカル実行ログ
- 大量の検証結果
- 個別環境依存の出力
- compiled binary model

## 16. 非スコープ

本ドキュメントでは、以下を非スコープとする。

- 個別テストケースの完全定義
- pytest 実装コード
- CI 実装詳細
- MuJoCo viewer の環境依存テスト
- OS / GPU / OpenGL 互換性テスト
