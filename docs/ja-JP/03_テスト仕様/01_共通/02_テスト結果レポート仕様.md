# テスト結果レポート仕様

## 1. 本ドキュメントの目的

本ドキュメントは、SansaVRM-MuJoCo-Adapter におけるテスト結果レポートの記録方針、記録項目、集計項目、Git 管理方針を定義する。

テスト結果レポートは、ローカル環境、MJCF 読み込み、変換処理、controller_config、runtime_requirements、updated_extension_properties、diagnostics などの検証結果を再確認できるようにするための成果物である。

## 2. 基本方針

テスト結果レポートは、テスト番号単位で記録する。

各テスト結果は、対応するテスト仕様、入力、期待結果、実行結果、判定結果を追跡できなければならない。

Extension Property 分類、runtime 成果物分離、updated_extension_properties 生成を検証した場合、その結果を集計または参照できなければならない。

ローカル環境依存の実行結果は Git 管理対象外とする。

小規模なサンプルレポートまたは schema は Git 管理対象としてよい。

## 3. レポート形式

初期段階では、テスト結果レポートは JSON 形式を標準とする。

必要に応じて、人間が読むための Markdown 要約を併用してよい。

標準ファイル名は以下とする。

```text
test_report.json
```

ローカル専用のテスト結果は以下の名称を使用できる。

```text
test_report.local.json
```

`test_report.local.json` は Git 管理対象外とする。

## 4. レポート全体の記録項目

テスト結果レポート全体は、少なくとも以下を持つ。

- report_id
- generated_at
- repository
- branch
- commit_sha
- test_target
- environment
- summary
- artifact_summary
- results

## 5. environment

environment は、テスト実行環境を記録する。

初期候補は以下とする。

- os
- os_version
- python_version
- mujoco_version
- adapter_version
- required_runtime_version
- execution_mode
- viewer_used

`execution_mode` は以下のいずれかとする。

- `headless`
- `viewer`
- `ci`
- `manual`

## 6. summary

summary は、テスト結果の集計を記録する。

summary は、少なくとも以下を持つ。

- total
- passed
- failed
- skipped
- error
- coverage

coverage は、単体テスト対象モジュールのカバレッジ率を記録する。

単体テストを作成する場合、対象モジュールのカバレッジ率は 100% を必須とする。

## 7. artifact_summary

artifact_summary は、テストにより生成または検証した成果物の集計を記録する。

初期候補は以下とする。

- generated_mjcf_count
- generated_controller_config_count
- generated_runtime_requirements_count
- generated_updated_extension_properties_count
- generated_conversion_report_count
- generated_diagnostics_count
- extension_property_classification_count
- runtime_artifact_separation_count
- source_raw_preserve_count
- unsupported_count

## 8. results

results は、テスト番号単位の結果一覧である。

各 result は、少なくとも以下を持つ。

- test_id
- test_name
- category
- status
- input
- expected
- actual
- diagnostics_ref
- report_ref
- duration_ms

## 9. test_id

test_id は、テスト番号を表す。

テスト番号は以下の形式とする。

```text
T-<AREA>-<NUMBER>
```

例：

```text
T-LOCAL-001
T-MJCF-001
T-ACTUATOR-001
T-EXTENSIONPROPERTY-001
T-RUNTIMEREQUIREMENTS-001
```

## 10. status

status は、テスト結果を表す。

status は以下のいずれかとする。

- `pass`
- `fail`
- `skip`
- `error`

## 11. input

input は、テストに使用した入力を記録する。

初期候補は以下とする。

- input_file
- input_data
- fixture
- command
- target_mujoco_version
- extension_property_fixture
- extension_property_schema
- custom_parameter_schema

## 12. expected

expected は、期待結果を記録する。

初期候補は以下とする。

- expected_status
- expected_output
- expected_diagnostics
- expected_exception
- expected_counts
- expected_extension_property_classification
- expected_runtime_requirements
- expected_updated_extension_properties

## 13. actual

actual は、実行結果を記録する。

初期候補は以下とする。

- actual_status
- actual_output
- actual_diagnostics
- actual_exception
- actual_counts
- actual_extension_property_classification
- actual_runtime_requirements
- actual_updated_extension_properties

## 14. diagnostics_ref

diagnostics_ref は、diagnostics との対応を記録する。

テスト実行中に diagnostics が生成された場合、対応する diagnostic_id を記録する。

複数の diagnostics に対応する場合は、配列として保持する。

## 15. report_ref

report_ref は、conversion_report などの関連成果物への参照を記録する。

初期候補は以下とする。

- conversion_report_id
- controller_config_path
- runtime_requirements_path
- updated_extension_properties_path
- generated_mjcf_path
- diagnostics_path

## 17. Markdown要約案

人間が読むための Markdown 要約を作成する場合、以下の項目を含める。

- 実行日時
- 対象ブランチ
- 対象コミット
- 実行環境
- MuJoCo バージョン
- テスト件数
- 成功件数
- 失敗件数
- スキップ件数
- エラー件数
- 主要な失敗理由
- runtime_requirements 検証結果
- updated_extension_properties 検証結果
- Extension Property 分類結果

## 18. Git管理方針

以下は Git 管理対象とする。

- テスト結果レポート仕様
- テスト結果レポート schema
- 小規模なサンプルレポート

以下は Git 管理対象外とする。

- `test_report.local.json`
- ローカル実行ログ
- 大量のテスト結果
- OS / GPU / OpenGL 依存の一時結果

## 19. diagnosticsとの関係

テスト結果レポートは、diagnostics の内容を複製してもよいが、原則として diagnostic_id への参照を保持する。

diagnostics の詳細は diagnostics 成果物に記録し、テスト結果レポートでは判定に必要な範囲を記録する。

## 20. CIとの関係

CI を導入する場合、CI 実行結果も本仕様に基づいて記録する。

CI では、headless テストを優先する。

MuJoCo viewer を必要とするテストは、初期段階では CI 必須対象に含めない。

Project Meridian runtime の実行を必要とするテストは、初期段階では CI 必須対象に含めない。

## 21. 非スコープ

本ドキュメントでは、以下を非スコープとする。

- CI workflow の詳細実装
- pytest 出力形式の完全定義
- 外部テストレポートサービス連携
- UI 表示仕様
- Project Meridian runtime の実行結果レポート仕様
- nisocon-vr-battle-runtime の試合結果レポート仕様
