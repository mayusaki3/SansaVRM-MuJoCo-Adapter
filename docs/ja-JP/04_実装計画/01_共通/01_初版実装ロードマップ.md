# 初版実装ロードマップ

## 1. 本ドキュメントの目的

本ドキュメントは、SansaVRM-MuJoCo-Adapter の初版実装へ進むための作業順序を定義する。

本ロードマップは、要件定義、仕様、テスト仕様、実装計画、テスト実装、Adapter 実装の順序を明確にし、実装前に必要なドキュメントと検証条件を整理するために使用する。

## 2. 基本方針

初版実装では、以下の順序を守る。

1. 要件定義を確定する
2. 仕様を確定する
3. テスト仕様を確定する
4. 最小サンプルを整備する
5. テストコードを作成する
6. Adapter 実装を作成する
7. テストを実行する
8. diagnostics / conversion_report を確認する

実装コードは、対応するテスト仕様とテストケースを定義した後に作成する。

## 3. 初版の到達目標

初版の到達目標は以下とする。

- ローカル MuJoCo 環境を構築できる
- 最小 MJCF モデルを読み込める
- `mj_step` を実行できる
- pytest によるローカル動作確認テストを実行できる
- 最小 MJCF 読み込みテストを実行できる
- position actuator サンプルを追加できる
- controller_config の最小出力方針を検証できる
- diagnostics の最小出力方針を検証できる

## 4. スコープ

初版実装のスコープは以下とする。

- ローカル MuJoCo 環境
- 最小 MJCF サンプル
- MJCF 読み込みテスト
- position actuator サンプル
- controller_config 最小 schema 案
- diagnostics 最小 schema 案
- pytest による headless テスト

## 5. 非スコープ

初版実装では、以下を非スコープとする。

- SansaVRM 本体 API との完全連携
- MJCF writer の完全実装
- URDF / VRM 変換
- MuJoCo viewer 必須テスト
- 実サーボとの sysid
- 強化学習環境
- controller runtime の実装
- UI / editor 実装

## 6. Phase 0: 現状確認

### 6.1 目的

既存ファイル、ブランチ、ドキュメント、サンプルの状態を確認する。

### 6.2 作業

- `develop` ブランチであることを確認する
- README が日本語であることを確認する
- `docs/ja-JP/目次.md` から作成済みドキュメントへ移動できることを確認する
- 各ドキュメントの階層リンクから目次へ戻れることを確認する
- `.gitignore` が存在することを確認する
- `requirements-dev.txt` が存在することを確認する
- `examples/mujoco/minimal_body/model.xml` が存在することを確認する

### 6.3 完了条件

- 作成済みドキュメントへのリンクが有効である
- 目次へ戻る階層リンクが有効である
- ローカル MuJoCo 検証に必要な最小ファイルが存在する

## 7. Phase 1: ローカル環境検証

### 7.1 目的

MuJoCo Python 環境がローカルで動作することを確認する。

### 7.2 作業

- `.venv` を作成する
- `requirements-dev.txt` をインストールする
- `mujoco` を import する
- `examples/mujoco/minimal_body/model.xml` を読み込む
- `mj_step` を実行する

### 7.3 対応テスト

- T-LOCAL-001
- T-LOCAL-002
- T-LOCAL-003
- T-LOCAL-004
- T-LOCAL-005

### 7.4 完了条件

- `mujoco` を import できる
- 最小 MJCF を読み込める
- `MjData` を生成できる
- `mj_step` を実行できる

## 8. Phase 2: pytest化

### 8.1 目的

ローカル動作確認を pytest で自動実行できるようにする。

### 8.2 作業

- `tests/mujoco/test_local_mujoco_environment.py` を作成する
- T-LOCAL-001 から T-LOCAL-005 を test 関数として実装する
- `pytest` を実行する
- coverage 計測対象を整理する

### 8.3 完了条件

- `pytest` で T-LOCAL-001 から T-LOCAL-005 を実行できる
- すべて pass する
- ローカル生成物が Git 管理対象外である

## 9. Phase 3: MJCF読み込みサンプル拡張

### 9.1 目的

最小 body 以外の MJCF 読み込みサンプルを段階的に追加する。

### 9.2 作業

以下のサンプルを追加する。

- `examples/mujoco/joint_body/model.xml`
- `examples/mujoco/position_servo/model.xml`
- `examples/mujoco/sensor_body/model.xml`

### 9.3 対応テスト

- T-MJCF-001
- T-MJCF-002
- T-MJCF-003
- T-MJCF-004

### 9.4 完了条件

- 追加した MJCF サンプルを MuJoCo で読み込める
- `tests/mujoco/test_mjcf_loading.py` で読み込み確認できる

## 10. Phase 4: アクチュエータ写像fixture整備

### 10.1 目的

### 10.2 作業

- `tests/fixtures/actuator/velocity_actuator.json`
- `tests/fixtures/actuator/torque_actuator.json`
- `tests/fixtures/actuator/unsupported_control_mode.json`

### 10.3 対応テスト

- T-ACTUATOR-001
- T-ACTUATOR-002
- T-ACTUATOR-003
- T-ACTUATOR-004
- T-ACTUATOR-005
- T-ACTUATOR-006
- T-ACTUATOR-007

### 10.4 完了条件

- fixture が JSON として読み込める
- fixture と期待結果の対応が明確である

## 11. Phase 5: controller_config最小検証

### 11.1 目的

controller_config の最小構造を生成・検証できるようにする。

### 11.2 作業

- `schemas/controller_config.schema.json` の最小版を作成する
- `tests/fixtures/controller_config/minimal_controller_config.json` を作成する

### 11.3 対応テスト

- T-CONTROLLERCONFIG-002
- T-CONTROLLERCONFIG-003
- T-CONTROLLERCONFIG-004
- T-CONTROLLERCONFIG-005
- T-CONTROLLERCONFIG-006
- T-CONTROLLERCONFIG-007

### 11.4 完了条件

- controller_config の最小 JSON を検証できる
- command delay / deadband / current limit / voltage limit の項目を確認できる

## 12. Phase 6: diagnostics最小検証

### 12.1 目的

diagnostics の最小構造を生成・検証できるようにする。

### 12.2 作業

- `schemas/diagnostics.schema.json` の最小版を作成する
- `tests/fixtures/diagnostics/minimal_diagnostics.json` を作成する
- diagnostics 参照を controller_config テストと接続する

### 12.3 完了条件

- diagnostics の最小 JSON を検証できる
- severity / category / code / target_type / target_id を確認できる

## 13. Phase 7: Adapter skeleton作成

### 13.1 目的

将来の実装に向けて、最小構成の Python package skeleton を作成する。

### 13.2 作業

以下を作成する。

- `src/sansavrm_mujoco_adapter/__init__.py`
- `src/sansavrm_mujoco_adapter/diagnostics.py`
- `src/sansavrm_mujoco_adapter/controller_config.py`
- `src/sansavrm_mujoco_adapter/mjcf_loader.py`

### 13.3 完了条件

- import できる
- テストコードから参照できる
- docstring とコメントがある
- 変更履歴コメントを含まない

## 14. Phase 8: CI導入検討

### 14.1 目的

GitHub Actions による headless テスト実行を検討する。

### 14.2 作業

- Python setup を定義する
- dependencies install を定義する
- pytest 実行を定義する
- MuJoCo headless 実行に必要な条件を確認する

### 14.3 完了条件

- CI 導入可否を判断できる
- viewer に依存しないテストのみを対象にできる

## 15. 初版完了条件

初版実装ロードマップの完了条件は以下とする。

- ローカル MuJoCo 環境を構築できる
- T-LOCAL-001 から T-LOCAL-005 を pytest で実行できる
- T-MJCF-001 を pytest で実行できる
- controller_config 最小 schema 案がある
- diagnostics 最小 schema 案がある
- Adapter skeleton を import できる
