# 初版実装ロードマップ

## 1. 本ドキュメントの目的

本ドキュメントは、SansaVRM-MuJoCo-Adapter の初版実装へ進むための作業順序を定義する。

本ロードマップは、要件定義、仕様、テスト仕様、実装計画、テスト実装、Adapter 実装の順序を明確にし、実装前に必要なドキュメントと検証条件を整理するために使用する。

## 2. 基本方針

初版実装では、以下の順序を守る。

1. 要件定義を確定する
2. 仕様を確定する
3. テスト仕様を確定する
4. 最小サンプルを整備する
5. テストコードを作成する
6. Adapter 実装を作成する
7. テストを実行する
8. diagnostics / conversion_report を確認する

実装コードは、対応するテスト仕様とテストケースを定義した後に作成する。

SansaVRM Rust モジュールと連携する本実装は、SansaVRM 側の Adapter 入力 JSON 仕様が確定するまで正本実装として扱わない。

ただし、SansaVRM 側から仮 schema / fixture / classifier / writer の draft 実装を進めてよい旨が回答されたため、Adapter 側では draft / provisional / experimental であることを明示したうえで先行実装できる。

## 3. 初版の到達目標

初版の到達目標は以下とする。

- ローカル MuJoCo 環境を構築できる
- 最小 MJCF モデルを読み込める
- `mj_step` を実行できる
- pytest によるローカル動作確認テストを実行できる
- 最小 MJCF 読み込みテストを実行できる
- position actuator サンプルを追加できる
- controller_config の最小出力方針を検証できる
- diagnostics の最小出力方針を検証できる
- runtime_requirements の最小出力方針を検証できる
- updated_extension_properties の最小出力方針を検証できる
- sansavrm_adapter_input の draft schema / fixture を検証できる

## 4. スコープ

初版実装のスコープは以下とする。

- ローカル MuJoCo 環境
- 最小 MJCF サンプル
- MJCF 読み込みテスト
- position actuator サンプル
- controller_config 最小 schema 案
- diagnostics 最小 schema 案
- runtime_requirements 最小 schema 案
- updated_extension_properties 最小 schema 案
- sansavrm_adapter_input draft schema 案
- pytest による headless テスト
- SansaVRM 連携構成の開発用/利用用境界整理

## 5. 非スコープ

初版実装では、以下を非スコープとする。

- SansaVRM 本体 API との完全連携
- SansaVRM Rust モジュール内部構造への直接依存
- sansavrm_adapter_input schema を SansaVRM 正本仕様として確定すること
- draft / provisional / experimental を正本仕様として扱うこと
- MJCF writer の完全実装
- URDF / VRM 変換
- MuJoCo viewer 必須テスト
- 実サーボとの sysid
- 強化学習環境
- Project Meridian / meridian-mujoco-runtime の実装
- HIL / SIL bridge の実装
- controller runtime の実装
- nisocon-vr-battle-runtime の実装
- UI / editor 実装

## 17. SansaVRM側ゲート

### 17.1 目的

SansaVRM Rust モジュールとの本格連携実装へ進む前に、SansaVRM 側で確定が必要な入力境界と、Adapter 側で先行可能な draft 実装範囲を明確にする。

### 17.2 正本化待ち対象

以下は SansaVRM 側の正本仕様確定後に再検証する。

- Adapter 入力用 JSON の正式仕様
- `sansavrm_adapter_input.json` の正式 schema
- `extension_properties` の正式構造
- `extension_property_schemas` の正式構造
- `custom_parameters` と Extension Property の正式関係
- `updated_extension_properties.json` の正式取り込み方針
- SansaVRM Rust CLI または export API の正式形式
- diagnostics / conversion_report の正式 schema

### 17.3 Adapter側で先行可能な範囲

SansaVRM 側正本仕様の確定前でも、以下は draft / provisional / experimental として先行可能とする。

- `sansavrm_adapter_input.schema.draft.json` の作成
- `sansavrm_adapter_input` fixture の作成
- Extension Property classifier の draft 実装
- runtime_requirements writer の draft 実装
- updated_extension_properties writer の draft 実装
- MJCF writer の段階実装
- CI / pytest / coverage の確認

### 17.4 Adapter側で正本扱いしない範囲

以下は、SansaVRM 側の正本仕様確定前に正本扱いしてはならない。

- `sansavrm_adapter_input.schema.draft.json`
- `sansavrm_adapter_input` fixture
- Extension Property classifier の分類結果
- updated_extension_properties の取り込み前提
- Core semantic candidate の扱い

### 17.5 再開条件

以下のいずれかが満たされた場合、正本仕様に基づく本格連携実装を再開できる。

- SansaVRM 側で Adapter 入力用 JSON 仕様が確定する
- SansaVRM 側で暫定 schema と fixture が提示される
- SansaVRM 側から、Adapter 側 draft schema を正本仕様へ昇格または修正する方針が提示される

- diagnostics 最小 schema 案がある
- runtime_requirements 最小 schema 案がある
- updated_extension_properties 最小 schema 案がある
