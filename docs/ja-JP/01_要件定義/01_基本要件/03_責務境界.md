# 責務境界

## 1. 本ドキュメントの目的

本ドキュメントは、SansaVRM 本体、SansaVRM-MuJoCo-Adapter、Project Meridian / meridian-mujoco-runtime、nisocon-vr-battle-runtime、MuJoCo の責務境界を定義する。

責務境界は、SansaVRM Core 標準仕様に MuJoCo / Project Meridian / sysid / HIL-SIL 固有情報を直接持ち込まず、SansaVRM-MuJoCo-Adapter に MuJoCo runtime / sysid / HIL-SIL / 試合進行の責務を持ち込まないために定義する。

## 2. 基本方針

SansaVRM 本体は、Core 標準構造と Extension Property を保持する。

SansaVRM Core は、外部フォーマット間の semantic integration を目的とし、特定 runtime、特定 adapter、特定 hardware、特定 firmware、特定 sysid 結果へ依存してはならない。

MuJoCo / Project Meridian / sysid / HIL-SIL 固有情報は、SansaVRM Core 標準仕様ではなく SansaVRM Extension Property として扱う。

SansaVRM-MuJoCo-Adapter は、SansaVRM 本体 API から取得した Core 標準構造と Extension Property をもとに、MuJoCo 固有の変換、近似、補助成果物生成、検証を行う。

Adapter は、SansaVRM 本体の内部データ構造へ直接依存してはならない。

## 3. 全体の責務関係

全体の責務関係は以下とする。

```text
SansaVRM
  ↓
SansaVRM-MuJoCo-Adapter
  ↓
Project Meridian / meridian-mujoco-runtime
  ↓
MuJoCo

nisocon-vr-battle-runtime
  ↓ uses
meridian-mujoco-runtime
```

## 4. SansaVRM本体の責務

SansaVRM 本体は、以下を担当する。

- SansaVRM Core 共通仕様の管理
- Module / Connection / Slot / Property の共通表現
- structure semantic の保持
- transform semantic の保持
- humanoid semantic の保持
- expression semantic の保持
- basic physics semantic の保持
- Extension Property の保持
- Extension Property Schema の管理
- namespace 付き custom parameter の保持
- custom parameter schema の管理
- Adapter が参照する入出力 API の提供
- Adapter から返却された diagnostics の保持
- Adapter から返却された updated_extension_properties の保持

SansaVRM 本体は、以下を担当しない。

- MuJoCo runtime の実行
- sysid optimizer
- HIL / SIL bridge
- 実ボード通信
- device specific driver
- ニソコンVRの試合・ルール・判定・進行管理

## 5. Extension Propertyの責務

Extension Property は、SansaVRM Core に固定導入しない追加情報を保持する。

以下は Extension Property として扱う。

- device_category
- device_identity
- capability_profile
- command_semantics
- command_transport
- actuator_model
- behavior_model
- sysid_result_ref
- runtime_requirements
- HIL / SIL metadata
- Project Meridian runtime metadata
- controller_config metadata
- diagnostics_ref
- conversion_report_ref
- source_raw

custom parameter は、Extension Property の一種として扱う。

## 6. SansaVRM-MuJoCo-Adapterの責務

SansaVRM-MuJoCo-Adapter は、以下を担当する。

- SansaVRM API からの情報取得
- SansaVRM Core 標準構造の読み取り
- Extension Property の読み取り
- Extension Property Schema に基づく分類
- SansaVRM から MJCF への変換
- 必要に応じた MJCF から SansaVRM への変換
- MuJoCo actuator への写像
- controller_config の生成
- runtime_requirements の生成
- updated_extension_properties の生成
- MuJoCo 固有パラメータの解釈
- MuJoCo 固有の近似変換
- diagnostics の生成
- conversion_report の生成
- MuJoCo 実行環境に依存する最小検証

SansaVRM-MuJoCo-Adapter は、以下を担当しない。

- SansaVRM Core 標準仕様への MuJoCo 固有情報の統合
- MuJoCo runtime の継続実行
- Project Meridian / meridian-mujoco-runtime の実装
- sysid optimizer
- 実測ログ処理
- HIL / SIL bridge
- 実ボード通信
- device specific driver
- ニソコンVRの試合・ルール・判定・進行管理

## 7. Project Meridian / meridian-mujoco-runtimeの責務

Project Meridian / meridian-mujoco-runtime は、以下を担当する想定とする。

- MuJoCo runtime の継続実行
- MuJoCo model load / step
- sensor output
- actuator command input
- controller loop
- ActuatorModel runtime
- DeviceCategoryModel
- DeviceSpecificModel
- sysid_result の適用
- sysid optimizer
- SIL
- HIL bridge
- 実ボード同期
- ログ出力

SansaVRM-MuJoCo-Adapter は、meridian-mujoco-runtime が必要とする情報を runtime_requirements へ分離するが、runtime 自体は実装しない。

## 8. nisocon-vr-battle-runtimeの責務

nisocon-vr-battle-runtime は、以下を担当する想定とする。

- 試合開始 / 終了
- ルール適用
- 勝敗判定
- スコアリング
- ラウンド進行
- プレイヤー管理
- レギュレーション管理
- 競技種目別ルール
- VR側表示 / 観戦 / 進行用イベント

SansaVRM-MuJoCo-Adapter は、nisocon-vr-battle-runtime と直接結合しない。

nisocon-vr-battle-runtime は、meridian-mujoco-runtime の抽象 API を通じて MuJoCo 実行結果を利用する。

## 9. MuJoCo本体の責務

MuJoCo 本体は、以下を担当する。

- MJCF 読み込み
- 物理計算
- actuator 入力の適用
- sensor 値の生成
- `mj_step` による step 実行

MuJoCo 本体は、SansaVRM、Adapter、Project Meridian、nisocon-vr-battle-runtime の責務を持たない。

## 10. 入出力境界

SansaVRM 本体と Adapter の入出力境界は、SansaVRM 本体が提供する公開 API とする。

Adapter は、以下の情報を API 経由で取得する。

- model metadata
- modules
- connections
- slots
- properties
- physics parameters
- joints
- colliders
- actuators
- sensors
- Extension Property
- Extension Property Schema
- custom parameters
- custom parameter schemas

## 11. MJCFと補助成果物の境界

MJCF へ直接出力できる情報は、SansaVRM 側の Extension Property Schema または custom parameter schema に定義された `io_scope` と `mjcf_mapping` に基づいて判定する。

MJCF へ直接出力しない情報は、`adapter_artifact` に基づき、controller_config などの Adapter 側補助成果物へ分離する。

Project Meridian / meridian-mujoco-runtime へ渡す必要がある情報は、`external_runtime_mapping` に基づき、runtime_requirements などの runtime 連携成果物へ分離する。

この判定を実装側の推測で行ってはならない。

## 12. 非可逆情報の扱い

変換により完全再現できない情報、未対応情報、fallback 適用情報は diagnostics または conversion_report に記録する。

必要に応じて、SansaVRM 本体側の source_raw、custom parameter、または Extension Property として保持する。

## 13. 変更時の原則

責務境界を変更する場合は、以下の順に更新する。

1. 要件定義
2. 仕様
3. テスト仕様
4. 実装計画
5. トレーサビリティ
